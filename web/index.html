Three bets that distinguish it

Numbers never pass through the model. The JSON can't ship if it contradicts itself. The SHA-256 fingerprint is part of the record's identity.

01

Deterministic-first extraction

PDF tables are read in code (pdfplumber); the model only fills gaps (audit opinion, notes, segments). Numbers never pass through the model.

A 270M local model produces the same numerical contract as a frontier cloud model. basis: "parsed" ≠ basis: "llm" in every line item.

02

Math-identity gate at the write path

If Assets ≠ L + Equity within a sector-aware tolerance, the record doesn't ship. Eleven cross-cutting + twenty-five issuer-specific pre-flag rules run before save().

Blocked records stay on disk with evidence pointing at the offending line item. They never propagate to a downstream pipeline.

03

SHA-256 + Sigstore + SLSA L3

Re-ingesting the same PDF on any engine commit produces bit-identical JSON, attested back to the engine commit that produced it via Sigstore keyless signing + SLSA v1 provenance.

Audit trail works without trusting the operator. A third party can verify "this PDF produced this JSON on this commit" from the public attestations alone.

Install in one command

Three public install paths — pick whichever fits your infrastructure. No PyPI Trusted Publisher click required.

Direct from GitHub Releases

pip install https://github.com/Mine-FNL/qstocks-filing-tool/releases/latest/download/qscreen_filing_tool-1.6.0-py3-none-any.whl

PEP 503 simple index (PyPI-equivalent)

pip install --extra-index-url https://mine-fnl.github.io/qstocks-filing-tool/simple/ qscreen-filing-tool

Container (multi-arch)

docker pull ghcr.io/Mine-FNL/qstocks-filing-tool:v1.6.0

30-second try it

pip install https://github.com/Mine-FNL/qstocks-filing-tool/releases/latest/download/qscreen_filing_tool-1.6.0-py3-none-any.whl
